# Nothing Wrong — обязательные инструкции Codex

## Начало работы

1. Общаться с владельцем по-русски.
2. Перед каждой задачей читать этот файл и подходящий документ из `DESIGN/`.
3. Для задач по HOI4 начинать с `.agents/skills/hoi4-project-router/SKILL.md`, затем применять профильный навык.
4. Активная игровая сборка — корень этого репозитория. Архивы, отчёты старых версий и внешние ZIP служат только источниками для сравнения.
5. Перед работой проверять `git status --short`; сохранять пользовательские изменения и держать diff небольшим.

## Приоритет источников

Последнее прямое указание владельца > явно утверждённое задание куратора > актуальный код и датированные документы > старые отчёты и предложения > внешние референсы.

Куратор помогает проектировать и проверять решения, но окончательные решения по лору, карте и политическим маршрутам принимает владелец.

## Запрет на несогласованные изменения карты

Без отдельного прямого задания не изменять:

- `history/states/`;
- state ID и имена state-файлов;
- provinces, owners, controllers, cores и claims;
- столицы и территориальные границы.

Канон владельца: **88 = Krakow, 89 = Stanislavov, 90 = Kielce, 91 = Lwow**. Имя state-файла не является источником истины. Подробности: `DESIGN/STATE_ID_CANON.md` и `DESIGN/MAP_DO_NOT_TOUCH.md`.

## Россия: защищённые правки 0.27.2

Не возвращать старые обязательные цепочки:

- `NW14_SOV_succession_memorandum` требует только `NW14_SOV_medical_council`;
- `NW14_SOV_russian_crossroads` требует только `NW14_SOV_succession_memorandum`;

## Лор и дизайн

- Первая мировая война не произошла; ванильные послевоенные последствия нельзя переносить автоматически.
- Не создавать государства, политические исходы и территориальные изменения без согласования.
- Сохранять уже работающий контент; не переписывать систему без доказанной необходимости.
- Экономические и военные программы независимы от политического пути, пока владелец явно не изменит это правило.
- Германия сохраняет механику Рейхстага; места, идеологии и коалиция — разные данные.
- Не создавать вторую параллельную механику здоровья/доверия Алексея II.
- Для новых визуальных решений ориентироваться на качественные открытые моды; RoIMOL не использовать как эталон.

## Качество и проверка

- Не угадывать команды, эффекты, триггеры, технологии, варианты техники и поля GUI: сверять с активным кодом и оригинальными файлами целевой версии игры.
- Проект рассчитан на HOI4 1.19.*; последняя сообщённая пользователем версия — 1.19.1.
- Несколько `focus` в одном `prerequisite` означают OR; отдельные блоки `prerequisite` — AND.
- Сохранять русский UTF-8 BOM в локализации.
- По умолчанию использовать ванильные GFX. Не генерировать исторические флаги.
- Стартовый сценарий задавать через history/common, а не через глобальную раздачу мира в `on_actions`.
- Перед и после изменений запускать `python tools/validate_project.py`.
- Статический анализ, предпросмотр и реальный запуск HOI4 всегда обозначать раздельно.
- Не считать задачу проверенной в движке без запуска игры и свежих логов.
- Не устанавливать сторонние skills, плагины или MCP без разрешения владельца.
- Не публиковать, не пушить и не отправлять материалы третьим лицам без поручения владельца.

## Работа с файлами

- Перед изменением существующего игрового файла делать временную резервную копию согласно используемому HOI4-навыку, после проверки удалять её.
- Для каждой задачи сохранять понятный diff, результат проверок и краткий отчёт.
- Новые функции не добавлять в рамках исправления ошибки без явного согласования.
- На этапе инвентаризации игровые файлы и карта остаются неизменными.
